# Phase 3 — Synthetic MSME Data

This phase produces the foundation the entire POC validates against: two
synthetic MSME customers with one internally-consistent year of data (FY 2025-26),
plus the golden expected-output files the AI behavior is later graded on.

## The two-track generation design

The blueprint needs two very different kinds of synthetic content, so we use two
different tools — each for what it is genuinely best at.

**Track 1 — Deterministic Python (no LLM): the structured data.**
Anything that must reconcile and be reproducible is generated by seeded Python
(`tools/dataset/`). Transactions, daily balances, utilization, GST, repayments,
documents, CRM rows and the golden files all derive from one spec
(`tools/dataset/spec.py`). Re-running with the same seed produces byte-identical
CSVs. The validator proves the blueprint's Section 6.3 consistency rules.

**Track 2 — Foundry gpt-4.1 (one-time): the SOP/policy prose.**
The RAG corpus (`docs/sop/*.md`) is open-ended narrative with no single correct
answer — exactly what an LLM does well, and what the bank's own model should
author so the grounding/provenance story is clean. Generated once via
`tools/generate/generate-all.sh`, committed, then indexed by Phase 5.

This is why data generation is **not** in `rebuild-all.sh`: deterministic data is
rebuilt by `phase3-data/up.sh` (fast, free, idempotent), while the one-time AI
generation is a separate, committed step.

## Run it

```bash
# (one-time, needs `az login` + pip install openai azure-identity)
bash tools/generate/generate-all.sh        # writes docs/sop/*.md via gpt-4.1

# (repeatable, free, no Azure) — also invoked by rebuild-all.sh
bash infra/phase3-data/up.sh               # builds data/csv + validates 6.3 rules
bash infra/phase3-data/down.sh             # removes generated data/csv only
```

## What gets produced

- `data/csv/` — 34 CSVs in the blueprint Section 6.1 layout (master, accounts,
  credit, financials, operations, CRM, voice, golden expected-outputs).
- `data/knowledge_base/` — deterministic rule CSVs (product rules, document
  checklist) + the policy manifest (written by the SOP generator).
- `docs/sop/` — 9 MSME SOPs (one-time Foundry output).

## Consistency guarantees (proven by `validate_seed.py`)

15 checks, including: all 34 files present; full FK integrity; per-transaction
running balances reconcile when sorted by time; cheque returns cross-reference
real `is_return=Y` transactions; repayments link to loan-servicing debits;
Customer A credits trend up / B trend down; A ≤1 cheque return / B exactly 6;
B insurance expired + stock statement overdue; golden EWS carry false-positive
guardrails; 6 memo sections per customer; nudges reference real calls.
